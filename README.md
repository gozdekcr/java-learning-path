### 📓​ Things I Learned  
- **Class Names:** Class name and File name should be same. Otherwise your file wouldn't work.  
- **Scanner Buffer Issue:** This occurred to me when I write **nextLine** after **nextDouble** in file **"ScannerInput.java"**. Program didn't ask me the str. This is called *Scanner buffer issue* and if you write *nextLine* after *nextInt or nextDouble*, you will see this error. You can get rid of this writing **input.nextLine();** before nextLine.
- **Scanner belongs in main:** I made the mistake of putting `Scanner` inside a recursive method. Every time the method called itself and it asked for a new input.
- **void methods can't be recursive (for calculations):**  I tried to calculate factorial with a `void` method and print the result inside. But recursion works by returning values back up the chain so `void` doesn't work here.
- **Every path must return a value:** If a method is declared as `long` or `int`, Java requires ALL branches (if / else if / else) to have a `return` statement. Even if only one branch is missing it, the code won't work.
- **Polymorphism:** Polymorphism is not just about overriding methods in subclasses. It also means that different objects can be managed through a shared superclass reference (upcasting). Each subclass keeps its own behavior while being treated as the same type. We make it for making the code flexible and independent of specific object types.
- **Constructor:** A constructor is a special method that runs automatically when an object is created. Its name must match the class name and it has no return type, not even void. It's used to set initial values for fields. If you don't write one, Java provides a default constructor with no argument. Constructors can be overloaded, we can write multiple constructors with different parameters.
- **Encapsulation:** Encapsulation means keeping the fields of a class `private` and only letting outside code reach them through `public` `getter and setter` methods. This way we are in control of what gets read or changed.
- **Static:** `static` means the field or method belongs to the class itself, not to any object. Normal fields have a separate copy for each object, but a static field is shared by all of them. You cannot use instance fields inside a static method because there is no object, so there is no `this`.
- **Inheritance:** Inheritance lets a class (subclass) inherit fields and methods from another class (superclass) using the `extends` keyword. The subclass automatically gets everything from the parent and can add its own fields/methods or override existing ones. Java only supports single inheritance so a class can extend only one parent. A subclass can also call its parent's constructor using `super()`.
- **Abstract class:** An abstract class is a class that you cannot create an object from directly. For instance, `new Shape()` gives a compile error. We make a class abstract when it represents something too general to exist on its own. For example, a Shape doesn't make sense as a real object but a Circle or Rectangle does. Use an abstract class when your subclasses share some logic but also need to define their own version of certain behaviors.
- **Abstract methods:** Abstract methods are methods with no body that subclasses are forced to implement. So If the parent has an abstract method, every subclass must override that specific method. Otherwise the code won't compile. But just making a class abstract doesn't force subclasses to override anything. Only abstract methods do that.
- **Interface:** An interface defines what a class must do, not how. It allows us to do multiple inheritance in Java. We use the `implements` keyword for interface. Every method inside an interface is abstract and public by default so you don't need to write it, Java adds it automatically. Every variable inside an interface is public, static and final by default, again, you don't need to write it. However, you can use the `default` keyword to write a method with a body inside an interface. Classes that implement the interface don't have to override a default method, they can use it as is or override it if they want.
- **Abstract class vs. Interface:** Both force the classes below them to implement certain methods, but the rule is: if you want to share code, use an abstract class but if you want to define a contract, use an interface. An abstract class can have fields, constructors, and methods with a body. But an interface can't have any of that except default methods. Also, a class can only extend one abstract class but can implement multiple interfaces.
- **Inheritance vs. Interface:** Both let a class reuse or follow a structure defined elsewhere, but they serve different purposes. `extends` is for when two classes share an "is-a" relationship. For example: a Dog is an Animal, so it inherits fields and methods from Animal. `implements` is for when a class needs to fulfill a contract. For example: a Dog can swim, so it implements the Swimmable interface. The key difference is that you can only extend one class, but you can implement as many interfaces as you want.
